## 1. Rendering separation

### Simulation owners

- `scripts/combat/enemy_director.gd` owns regular-enemy lifecycle, targeting,
  movement, attacks, cleanup, stable visual IDs, and checkpoint persistence.
- `scripts/combat/longshadow_encounter.gd` owns Longshadow phase state,
  transition gates, attacks, response windows, completion, and checkpoint
  state.
- `scripts/run/game_world.gd` owns orchestration, world state, category routing,
  and snapshot publication.

### Presentation owners

- `scripts/combat/enemy_view_pool.gd` renders regular threats from
  `PresentationSnapshot`.
- `scripts/combat/longshadow_view.gd` renders Longshadow from snapshot state.
- `scripts/train/train_sprite_view.gd` is the routed M2 baked train facade.
- `scripts/world/world_sprite_view.gd` is the routed M2 baked world facade.
- `scripts/effects/vfx_pool.gd` is the routed M2 baked effects facade.
- The existing vector renderers remain the default shipping path until authored
  art replaces the placeholders.

The views do not mutate simulation state. Enemy animation time is copied from
simulation-owned time instead of wall-clock time, so pause, speed scaling,
headless execution, and restored runs stay coherent.

## 2. Snapshot boundary and ordering

`scripts/presentation/presentation_snapshot.gd` is the reusable read-only frame
boundary. It carries:

- simulation, enemy, and reference-frame clocks
- train position, scale, integrity, and car records
- light origin, direction, spread, range, and intensity
- route context and accessibility state
- regular-enemy records
- Longshadow phase, position, transition, response, and completion state
- dawn and capture metadata

`EnemyViewState` and `CarViewState` records are pooled. `begin_frame()` resets
active counts and records without rebuilding the backing arrays or per-frame
dictionaries. Consumers use `enemy_count` and `car_count`; retained capacity is
not interpreted as live state.

The live ordering is:

1. `GameWorld` advances Longshadow.
2. `EnemyDirector` completes the regular-enemy simulation tick.
3. `EnemyDirector.simulation_tick_completed` triggers snapshot publication.
4. Views redraw from the completed snapshot.

Reference scenarios disable automatic simulation, apply an exact point state,
set the capture clock, refresh presentation inputs, publish the snapshot, and
then capture after `RenderingServer.frame_post_draw`.

## 3. Event boundary

`scripts/presentation/presentation_event_bus.gd` now enforces producer roles at
emission time.

Every event requires:

- a registered producer ID
- a type declared by that producer
- an explicit deterministic timestamp
- stable source and target IDs
- position and direction
- strength and material
- optional structured payload

Both `SimEvent` and `PresentationEvent` use fixed pools. Dispatch is
synchronous: the bus snapshots diagnostic history, invokes registered consumer
callbacks and signals, resets the event, and immediately returns it to its
pool. Consumers copy primitive fields during the callback and do not retain the
pooled object.

The final QA path exercises both channels:

- simulation producer: `qa.reference_scenario.sim`
- presentation producer: `qa.reference_scenario.presentation`
- baked effects consumer: `VfxPool.on_event`

The effects category is no longer metadata-only. `EffectsLayer` owns the vector
route and `VfxPool` owns the baked route. Vector fallback explicitly enables
the legacy layer and disables the baked pool.

The twelve required signature loops are registered in

5. Focus
6. Ward shatter

Every scenario defines four ordered labels and exact trigger times.
`scripts/run/runtime_probe.gd` applies scenario-specific simulation state at
each point before the presentation refresh. The frames therefore show actual
progression instead of four labels over a frozen scene.

The capture harness records SHA-256 over raw viewport pixel bytes before PNG
encoding. `tools/qa/run_reference_scenarios.py` requires:

- 12 scenarios
- vector and baked routes for every scenario
- four ordered frames per route
- four distinct hashes inside every route
- identical stable IDs between vector and baked routes
- correct ownership of all five presentation categories
- real detachment completion with two cars remaining
- an exact clean-process replay match for all four hashes

## 5. Cross-run determinism correction

The final independent verification found that the first version of the capture
boundary was unique within one run but not reproducible across clean launches.
Vector ash, train smoke and sparks, effects aging, and transient HUD overlays
could advance according to wall-clock scheduling before a capture.

The correction adds an explicit reference-capture state to:

- `WorldRenderer`
- `TrainRenderer`
- `EffectsLayer`
- `VfxPool`
- `HUD`

Reference capture now:

- drives world and train animation from the declared frame time
- clears and reseeds transient vector particles before scenario setup
- prevents effects from aging on unscripted wall-clock deltas
- clears transient HUD notification, critical, and cinematic overlays
- reapplies the exact capture state before every rendered frame

`run_reference_scenarios.py` now reruns every scenario/route combination in a
clean process and rejects any hash mismatch. All 24 routes passed.

## 6. Save compatibility and stable IDs

Regular-enemy visual IDs use a deterministic counter seeded from `run_seed`.
The counter is stored in enemy checkpoint state, restored monotonically, and
does not reissue IDs after save/load.

The legacy save smoke test performs:

1. v0.7 fixture load
2. migration to the current schema
3. v0.8 resave
4. reload
5. equivalence validation

The deterministic smoke suite also covers campaign outcomes, route behavior,
archetypes, seed variance, profile invariance, event role enforcement, event
pool recycling, snapshot reuse, headless simulation, reference registry
coverage, and Longshadow checkpoint gates. Result: **ALL PASSED**.

## 10. Independent audit correction history

### First architecture audit

The first review rejected the initial implementation because event pools did
not recycle, producer roles were descriptive only, enemy presentation used
wall-clock time, the effects flag routed nothing, detachment was simulated
instead of using gameplay code, snapshot allocation claims were overstated,
and the capture scenarios did not prove exact frame sequences.

Corrections:

- enforced producers and declared event types
- synchronous dispatch and immediate pool recycling
- actual callback consumers
- simulation-owned animation time
- routed baked effects pool
- real gameplay detachment path
- pooled car and enemy snapshot records
- post-simulation snapshot ordering
- exact four-point scenario definitions

### Second capture audit

The second review found that four files were written per route but most frames
did not express meaningful visual progression. It also found that several
consumers ignored event fields and the presentation-only event channel was not
exercised.

Corrections:

- deterministic state mutations at every capture point
- event-field-driven emphasis in world, train, enemy, and Longshadow views
- QA `PresentationEvent` producer and baked VFX consumption
- raw-pixel SHA-256 evidence
- real-detachment final-state receipt

### Final reproducibility audit

The final review found cross-launch pixel drift, stale profile numbers, and a
stale package hash.

Corrections:

- deterministic reference clocks and transient-state reset
- clean-process replay verification for all 24 routes
- stable 60 FPS profile runner
- regenerated profile matrix, reference receipt, scorecard, and Web package
- corrected September 24 evidence throughout this audit

### Exact-diff signoff

An independent code review then inspected the exact final diff, recomputed the
source fingerprint, package hashes, package arithmetic, capture counts, replay
flags, stable IDs, detachment receipts, event-pool lifecycle, snapshot reuse,
save-ID monotonicity, and public deployment state. Verdict: **PASS**, with no
reportable functional or evidence defect.

The reviewer recorded one non-blocking naming note: a few GameWorld-originated
damage events use the simulation owner string as `source_id` because the
attacking entity is unavailable at that callback boundary. Current consumers
do not use source/target identity. Normalizing unknown-source semantics before
identity-driven consumers are added is recommended, but it is not an M2 gate.
