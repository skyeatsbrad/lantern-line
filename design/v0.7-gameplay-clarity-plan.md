# v0.7 Gameplay Clarity Plan

Date: September 22, 2026

## Goal

Turn the stable v0.6 presentation release into a stronger cross-device game by
fixing the documented route control, adapting the interface to the physical
browser window, teaching systems during play, and making strategic risk and
repair choices matter more.

## Research basis

- Godot's multiple-resolution guidance recommends `canvas_items` with `expand`
  for landscape mobile games, but the expanded logical viewport can differ
  substantially from the physical client area. `DisplayServer.window_get_size`
  provides that physical client size.
- Godot's `InputMap.action_get_events` exposes the actual configured action
  bindings, so documented shortcuts can be protected by automated tests.
- Xbox Accessibility Guideline 101 recommends readable default text and
  scalable interfaces that preserve content and function.
- Xbox Accessibility Guideline 107 requires digital alternatives and accurate
  control labels.
- Xbox Accessibility Guideline 109 recommends interactive, revisitable
  tutorials rather than relying on static control screens.

## Internal evidence

- Right Arrow did not commit the middle route in a public Chromium playtest.
  `choose_middle` was bound to Left Arrow.
- At 844 x 390, the Web build ran without errors but retained the desktop
  logical layout, shrinking text and clipping the lowest controls.
- A correct-input, safe-route run won without buying a Waypost refit, while the
  default Workshop repair rate erased too much sustained damage.
- Several danger routes paid less than danger-free alternatives.
- High Contrast labels were drawn in the same per-enemy pass as world
  silhouettes, allowing later ward graphics to cross earlier labels.

## Implementation stages

1. **Input correctness**
   - Bind middle-route commitment to Right Arrow.
   - Assert all three route bindings through `InputMap`.

2. **Physical-window responsive UI**
   - Preserve the user's 100%, 115%, or 130% preference.
   - Add an automatic scale floor derived from physical window dimensions.
   - Trigger compact layouts from physical or logical constraints.
   - Rebuild title and gameplay interfaces when the window changes.

3. **Staged onboarding**
   - Keep the complete Conductor's Guide available on demand.
   - Show only one quick-start page before the first run.
   - Teach pace and power priorities contextually during early travel.
   - Mention detachment only when the rear car becomes critical.

4. **Strategic pressure**
   - Require a powered Workshop for continuous repairs.
   - Lower baseline repair throughput so damage is persistent unless Repair is
     deliberately prioritized or upgraded.
   - Increase danger-route scrap and special-resource premiums.
   - Add no-refit and high-risk campaign probes.

5. **Dense-combat clarity**
   - Draw High Contrast labels after every silhouette, ward, warning, and bar.
   - Resolve label rectangles into separate rows and draw leader lines when a
     label must move.

6. **Release validation**
   - Run the complete deterministic suite.
   - Capture and inspect 1280 x 720, 960 x 540 accessibility, and 844 x 390
     physical-window layouts.
   - Export Web and Windows packages, mirror `docs`, and verify GitHub Pages.

## Acceptance criteria

- Up, Right, and Down commit upper, middle, and lower routes respectively.
- An 844 x 390 Web client automatically uses compact layout and a readable UI
  scale without changing the saved text preference.
- The first run requires one quick-start page, while the full four-page guide
  remains revisitable.
- Repairs stop when no powered Workshop is available.
- Danger routes have an explicit reward premium proportionate to their threat.
- High Contrast labels cannot be overdrawn by another enemy or ward.
- Source and packaged smoke suites, renderer probes, exports, and public boot
  verification pass.
