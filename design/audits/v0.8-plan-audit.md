# v0.8 Visual and Mobile Plan Audit

Date: September 23, 2026

Audited artifact:
`design/v0.8-visual-mobile-overhaul-plan.md`

Auditor: independent Claude Opus 4.7 research pass, followed by repository
verification and disposition by the implementing agent.

## Verdict

**GO.**

The 2.5D-with-selective-live-3D direction, mobile-first HUD, simulation/view
split, tool-sovereignty contract, and M0-M9 sequence are sound. The audit found
methodological and gating defects, not an architectural reason to restart.

The authoritative plan was revised before implementation begins.

## Verified baseline

- The five named immediate-mode renderers exist.
- Current public PCK is 3,816,264 bytes.
- v0.7 recorded 287 normal-gameplay, 451 dense-combat, and 345 audio-stress
  draw calls.
- The existing metrics probe does not discard warm-up or report percentiles.
- No explicit screen-touch or screen-drag input path exists.
- Longshadow's entrance and transition gates are 3.0 and 2.5 seconds.
- Godot 4.7 provides `InputEventScreenDrag.screen_relative`,
  `InputEventScreenTouch`, `VirtualJoystick`, and
  `DisplayServer.get_display_safe_area()`.
- RunState caps the consist at five cars.
- EnemyDirector caps active desktop pressure at twelve enemies and compact
  pressure at ten.

## Findings and dispositions

| ID | Severity | Finding | Disposition |
|---|---|---|---|
| F1 | Critical | Draw-call gates used a non-warm baseline while requiring warm percentile metrics. | Accepted. M0 now runs three warm measurements and publishes `design/audits/v0.8-baseline.md`; numeric gates reference it. |
| F2 | Critical | M2 did not prove the new views were ready to receive later assets. | Accepted. M2 now requires snapshot, asset attach/detach, profile, placeholder, event, and per-category fallback interfaces. |
| F3 | Critical | The original touch HUD inventory could exceed 844-pixel width. | Accepted. Lens and action controls became vertical thumb rails; power uses role chips plus a temporary level flyout. M1 requires a labeled 844 x 390 hit-region capture at all touch scales. |
| F4 | High | Controlled `.blend` sources lacked drift enforcement. | Accepted. `validate_blend.py` checks collections, topology, rigs, actions, sockets, and materials against manifests. |
| F5 | High | Package headroom was too loosely allocated. | Modified. Target increased to 22 MiB and hard ceiling to 26 MiB, with cumulative M3-M7 gates. Visual target remains 16 MiB because existing audio is already in the baseline and QA captures are excluded from export. |
| F6 | High | Desktop safe-area fallback is unreliable. | Accepted. Desktop returns zero insets; native uses DisplayServer; Web reads CSS environment insets through a probe element. |
| F7 | High | Exact Blender patch must be proven before hard pinning. | Accepted. M0 verifies one official 4.5.x archive URL and checksum and then commits an immutable pin. Runtime auto-discovery is not allowed after that. |
| F8 | High | `ScreenWorldMapper` lacked a coordinate specification. | Accepted. The plan now fixes reference viewport, orthographic size, cinematic viewport, Z ownership, and round-trip tests. |
| F9 | High | Live-3D benchmark was not representative enough. | Modified. It now uses the real five-car and twelve-enemy maxima, a sixteen-enemy headroom run, a separate boss run, full effect/HUD load, and three measured 30-second runs. The proposed 25 simultaneous enemies was rejected because the shipping simulation caps pressure at twelve. |
| F10 | Medium | Vector fallback was not explicitly manual-only. | Accepted. It is never auto-selected. |
| F11 | Medium | Simulation and presentation events were conflated. | Accepted. `SimEvent` and `PresentationEvent` are separate and connection-audited. |
| F12 | Medium | Tool sovereignty had no CI enforcement. | Accepted. `verify_provenance.py` is a mandatory stage check. |
| F13 | Medium | Cycles GPU/CPU output cannot be byte-identical. | Accepted. Canonical renders use CPU Cycles and OpenImageDenoise; local GPU renders use perceptual comparison only. |
| F14 | Medium | Autonomous playtesting cannot fully judge subjective feel. | Modified. User approval is not made a blocking production dependency because the user requested complete autonomous handling. The plan instead requires video/frame receipts, direct vision review, and an independent visual-critic pass; user feedback remains welcome but optional. |
| F15 | Medium | Snapshot cadence and interpolation were unspecified. | Accepted. Pooled physics snapshots and view interpolation are now explicit. |
| F16 | Low | Touch target size had no accessibility multiplier. | Accepted. Added 100%, 115%, and 130% touch scaling. |
| F17 | Low | ETC2/ASTC import is not enabled in the current project. | Accepted. M0 enables it, forces reimport, and verifies generated formats. |
| F18 | Low | Image QA dependencies were unnamed. | Accepted. Initial package families are listed and versions are locked in M0. |
| F19 | Low | Generated icons lacked accessible labels. | Accepted. Icon manifests now require `label_key`, accessible names, tooltips, and text fallbacks. |
| F20 | Low | Live-3D benchmark result had no permanent decision record. | Accepted. M0 publishes `design/decisions/v0.8-live-3d-boundary.md`, the sole authority for M6 scope. |

## Additional gate corrections

- Every stage runs deterministic smoke and profile-parity validation.
- From M2 onward, a known v0.7 save must load, resave, and reload with
  equivalent simulation state.
- Package ceilings are cumulative and stage-specific.
- Reduced Motion and High Contrast captures have measurable acceptance rules.
- M1 validates manifest, service-worker, icon, start-URL, orientation, and
  installed-mode behavior rather than relying on an editor checkbox.
- Generated visual files must trace to a source manifest, tool pin, build
  command, and hash.

## Remaining empirical unknowns

These are intentionally owned by M0/M1 rather than guessed in the plan:

1. The exact live-3D boundary on accelerated mobile Web.
2. The final warm p50/p95/p99 and draw-call baselines.
3. Whether Low is cheaper with half-resolution sprites or the vector fallback.
4. The final 844 x 390 touch geometry at 130% touch scale.
5. Actual iOS Safari/PWA behavior when physical or hosted device access is
   available.

## Final assessment

No unresolved audit finding blocks M0. The plan now protects visual ambition
without making opaque manual artwork a dependency, uses repository-realistic
performance loads, and establishes rollback and validation gates before any
large asset migration.
