# v0.8 M1 Mobile Platform and Touch Foundation Audit

- Date: 2026-09-23
- Baseline: `fe1a76d` (`Establish v0.8 visual and mobile foundation`)
- Verdict: **GO**
- Public deployment: remains on v0.7

## Scope

M1 adds the mobile input, layout, browser, and validation foundation required
before the v0.8 presentation overhaul continues:

- indexed touch ownership with simultaneous aim and HUD actions
- physical target sizing, safe areas, and 24 px comfort gutters
- a dedicated phone HUD and touch-specific overlays
- a source-controlled Web shell with launch, audio, fullscreen, orientation,
  wake-lock, PWA, and offline behavior
- deterministic touch, responsive-layout, browser, and save-safety gates

The complete dirty diff was independently reviewed after implementation and
again after every confirmed correction.

## Web, PWA, and responsive evidence

- Launch target: 192 x 48 CSS pixels.
- Canvas: 844 x 390 CSS pixels in the landscape gate.
- Safe-area bridge exposes left, top, right, and bottom values.
- Portrait touch sessions show the rotate-device overlay.
- Manifest uses standalone display, landscape orientation, and 144, 180, and
  512 px icons.
- A controlled second launch caches the large game assets.
- A full offline reload reaches the playable Godot canvas with no page or
  console errors.
- Desktop benchmark contexts select `standard` with touch layout disabled.
- Mobile touch contexts select `phone_touch`.

## Performance and package budget

Final WebGL 2 measurements use a 1-second warm-up and 3-second sample:

| Viewport | Sprite | Hybrid | Runtime 3D |
|---|---:|---:|---:|
| Desktop 1280 x 720 | 18.06 ms / 208 draws | 18.06 ms / 292 draws | 18.06 ms / 600 draws |
| Mobile 844 x 390 | 18.06 ms / 123 draws | 18.06 ms / 207 draws | 18.06 ms / 515 draws |

The production Web PCK is 3,898,584 bytes (3.72 MiB), below the 7 MiB M0
ceiling. The rendering boundary remains unchanged: baked sprites by default,
bounded hybrid presentation only on the High profile, and runtime 3D retained
as a benchmark-only comparison.

## Remaining limitation

Physical Android and iOS hardware verification remains pending. Browser
emulation proves responsive composition, input routing, cached offline launch,
and fallback behavior, but it cannot certify device-specific fullscreen,
orientation, wake-lock, audio-unlock, install, thermal, or touchscreen
behavior. This is a device-validation limitation, not an open M1 code defect.

## Decision

M1 is complete and may proceed to M2 rendering separation and fallback
routing. Public GitHub Pages deployment stays on v0.7 until the later release
candidate milestone.
