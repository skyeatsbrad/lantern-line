## Audit findings and dispositions

### Benchmark-scaffold audit

1. Hybrid boss rendered both 2D and 3D versions - fixed by reserving the boss
   for the hybrid live-3D viewport.
2. Texture cache keys ignored dimensions - fixed by including size and colors
   in deterministic keys.
3. Warm-up placeholders could become zero metrics - fixed by rejecting warm or
   incomplete records.
4. Receipt capture contaminated measured worst frames - fixed by capturing
   during warm-up.
5. Mode order introduced thermal bias - fixed by rotating architecture order.
6. Failed runs discarded completed work - fixed with retries and resumable
   partial records.

### Final M0 audit

1. Unbounded live percentile capture affected normal gameplay - fixed by
   making metrics opt-in, bounded, and snapshot-sorted.
2. Source fingerprints missed staged files - fixed by diffing tracked paths
   against `HEAD` and separately including untracked files. A staged-change
   reproduction changes the fingerprint.
3. Public Web URLs could activate the benchmark - fixed with a custom-feature
   gate and separate QA export preset. Playwright verifies the production
   query is blocked.
4. `BUILD_HASH.txt` entered release packages - fixed in every export filter and
   verified absent from built PCKs.

An independent closure review passed all four fixes and found no remaining
release blocker.

## Residual limitations carried forward

- QA orchestration currently targets Windows, Edge/ANGLE D3D11, and the pinned
  Windows Blender artifact.
- Browser phone dimensions are not physical-phone performance evidence.
  Hardware-accelerated Android-class validation is required before mobile live
  3D can be enabled; physical or hosted iOS Safari remains a release check.
- The current compact HUD is functional but visually dense and does not meet
  the M1 touch-layout contract.
- M0 contains no production v0.8 atlases or controlled `.blend` sources; the
  empty deterministic graph is intentional.
- Profile-specific renderer differences begin after the M2 view/fallback
  boundary. M0 validates profile plumbing, not final art parity.

## M1 authorization

M1 may begin with the dedicated input router, multi-touch ownership and
cancellation, safe-area bridge, custom Web shell/PWA support, physical target
helpers, and dedicated touch HUD. The M0 baselines and package limits are now
the numeric authorities for subsequent stage audits.
